# PoE 2 Clock Companion

Windows-помощник для физических часов PoE 2. Он оценивает Currency- и выбранные публичные вкладки, показывает мониторинг источников данных и динамику стоимости за игровую сессию. Пока подключение часов представлено эмулятором; COM-адаптер будет добавлен отдельным этапом. Консольный проект оставлен только для диагностики и ручной проверки API.

## Запуск

```powershell
dotnet run --project .\src\Poe2DesktopClock.Desktop\Poe2DesktopClock.Desktop.csproj -c Debug -p:Platform=x64
```

Только проверить сборку:

```powershell
dotnet build .\Poe2DesktopClock.sln -c Debug -p:Platform=x64
```

## Релизный пакет

Локальная release-сборка создаёт два варианта: устанавливаемый `MSIX` с package identity и переносимый self-contained `ZIP`, которому не нужен установленный .NET:

```powershell
.\scripts\Publish-Release.ps1 -Version 0.1.0 -GenerateDevelopmentCertificate
```

Артефакты появятся в `artifacts\release`. Development-сертификат не является публично доверенным, поэтому для локальной установки используйте:

```powershell
cd .\artifacts\release
.\Install-Poe2DesktopClock.ps1 -TrustCertificate
```

GitHub Actions выполняет ту же сборку после каждого `push` и сохраняет результат как workflow artifact. При отправке тега вида `v1.2.3` файлы автоматически добавляются в GitHub Release. Без настроенных секретов workflow подписывает MSIX временным development-сертификатом и кладёт рядом публичный `.cer`. Для стабильной подписи обновлений добавьте repository secrets:

- `MSIX_CERTIFICATE_BASE64` — PFX-сертификат для code signing в Base64;
- `MSIX_CERTIFICATE_PASSWORD` — пароль PFX.

Закрытый ключ и PFX в репозиторий не добавляются.

Для прежних диагностических команд (`status`, `debug-frame`, `currency`, `public`, `worth`):

```powershell
dotnet run --project .\src\Poe2DesktopClock.ConsoleDebug\Poe2DesktopClock.ConsoleDebug.csproj -c Debug -p:Platform=x64
```

## Первоначальная настройка

При первом запуске приложение открывает трёхшаговый мастер. После его завершения Dashboard откроется автоматически; при следующих запусках мастер не показывается. Уже полностью настроенные установки мигрируются без повторного онбординга.

1. Откройте в игре Currency-вкладку и нажмите «Выбрать область». Обведите вкладку — область сохраняется сразу после отпускания ЛКМ, без Enter. Затем нажмите «Настроить ячейки», при необходимости поправьте найденные рамки и подтвердите их клавишей Enter.
2. Укажите `AccountName` (полное имя с дискриминатором, например `SherlockDmt#3728`) и выберите лигу. Оставьте только публичные вкладки, которые хотите учитывать. Для каждой включённой вкладки мастер показывает точное техническое имя, например `~price 1001 mirror`; вкладка должна быть публичной и содержать хотя бы один предмет с этой маркерной ценой. Нажмите «Синхронизировать»: результат будет показан отдельно для каждой вкладки. Неудачную вкладку можно исправить и проверить снова либо исключить.
3. Экран подключения часов пока является заглушкой. Нажмите «Завершить настройку» — сразу откроется Dashboard, Currency-вкладка начнёт отслеживаться, а публичные вкладки будут обновляться в фоне.

Настройки разделены на вкладки «Общие», «Вкладка валюты», «Публичные вкладки» и «Сброс». В них доступны частота проверки Currency-вкладки (2 или 3 кадра в секунду), подключение и отключение отдельных публичных вкладок, фоновое обновление источников, запуск в свёрнутом виде и системная рамка захвата Windows. Для отключения жёлтой рамки установите MSIX-пакет, снимите флажок «Показывать системную рамку захвата Windows» и подтвердите системное разрешение; на Windows старше версии 2104 и в portable-сборке рамка может остаться. Новую публичную вкладку нужно проверить через Trade API перед сохранением; уже подключённую можно отключить без повторной проверки. При нажатии на крестик окно скрывается в области уведомлений Windows: двойной клик по значку или пункт «Открыть» вернёт его, а «Выход» полностью остановит приложение и мониторинг.

## Как работает мониторинг

Когда игра и откалиброванная Currency-вкладка доступны, приложение делает снимок выбранной области 2–3 раза в секунду. Сначала оно сравнивает только зоны цифр стеков. OCR и пересчёт выполняются по этому же снимку лишь когда зоны изменились — повторный захват окна не нужен. Раз в секунду дополнительно проверяется геометрия вкладки: поэтому пустая открытая Currency-вкладка тоже определяется корректно. При закрытой вкладке последнее валидное значение сохраняется — нули не подставляются.

Публичные вкладки не опрашиваются на каждом кадре: это отдельная точная операция Trade API. Последний её результат объединяется с последним успешным сканированием Currency-вкладки. Если Trade API вернул неполный результат, слишком много листингов или устаревшие данные, интерфейс помечает общую оценку как неполную, а не выдаёт её за точную.

Последний рассчитанный снимок сохраняется локально. Когда запускается процесс PoE 2, он становится начальной точкой новой игровой сессии. На Dashboard показываются изменение стоимости и `div/ч`; пока игра не запущена, эти показатели не рассчитываются. Если приложение ещё никогда не получало оценку, первая успешная оценка становится начальной точкой сессии.

## Структура решения

```text
src/
  Poe2DesktopClock.Domain                 Правила продукта и value objects
  Poe2DesktopClock.Contracts              DTO для границ приложения
  Poe2DesktopClock.Application            Контракты пользовательских сценариев
  Poe2DesktopClock.Infrastructure.PoeApi  Адаптеры Trade API и poe.ninja
  Poe2DesktopClock.Infrastructure.Storage JSON-хранилища настроек
  Poe2DesktopClock.Infrastructure.Windows Захват окна, OCR, Win32 и калибровка
  Poe2DesktopClock.Desktop                WPF companion и мониторинг источников
  Poe2DesktopClock.ConsoleDebug           Отладочная консоль
```

`Domain` не зависит от UI, Win32, OCR, сети или application-контрактов; здесь лежат только правила продукта. `Contracts` содержит DTO для границ приложения: настройки, снимки и статусы. `Application` содержит use case-контракты. HTTP- и JSON-адаптеры независимы от Windows и могут работать в `net8.0`; в Windows-сборке остаются только platform-specific части. WPF и инфраструктура зависят от application-контрактов, а граф конкретных зависимостей собирается в `App`, не в `MainWindow`.

Старые калибровки и настройки публичных вкладок продолжают читаться из `%LOCALAPPDATA%\Poe2DeskTracker`, поэтому перенос проекта не сбрасывает уже сделанную настройку. Новые настройки Desktop-приложения хранятся в `%LOCALAPPDATA%\Poe2DesktopClock\settings.json`, состояние первоначального мастера — в `%LOCALAPPDATA%\Poe2DesktopClock\onboarding.json`, а последний снимок стоимости — в `%LOCALAPPDATA%\Poe2DesktopClock\last-clock-snapshot.json`.

Приложение не читает память игры и не отправляет в неё ввод. Для работы захвата требуется Windows 10 1903+ x64.
